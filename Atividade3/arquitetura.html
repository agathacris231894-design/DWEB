Arquitetura Moderna: Cloud, DevOps, Segurança, Observabilidade e IA

Cloud Computing

Utilização de recursos computacionais fornecidos por provedores de nuvem.

Pode incluir:

  • Máquinas virtuais;
  • Bancos de dados;
  • Armazenamento;
  • Redes;
  • Funções;
  • Serviços gerenciados.

Exemplos de provedores citados no material:

  • AWS;
  • Microsoft Azure;
  • Google Cloud.

Docker

Permite empacotar:
Aplicação + Dependências + Configuração → Container

Ajuda a manter consistência entre desenvolvimento, testes e produção.

Kubernetes

É uma plataforma para orquestração de containers.

Pode auxiliar em:

  • Escalabilidade;
  • Descoberta de serviços;
  • Atualizações;
  • Recuperação de containers;
  • Gerenciamento de workloads.

Terraform

Utilizado para Infraestrutura como Código (IaC).

Código → Terraform → Infraestrutura

Permite:

  • Versionamento;
  • Automação;
  • Repetibilidade;
  • Padronização.

DevOps e CI/CD

DevOps aproxima desenvolvimento e operações.

Fluxo:
Código → Build → Testes → Deploy → Monitoramento → Feedback

Envolve:

  • Automação;
  • CI/CD;
  • Infraestrutura como código;
  • Monitoramento;
  • Colaboração;
  • Entrega contínua.

CI

Continuous Integration
Integração frequente das alterações de código e sua validação.

CD

Pode significar:

  • Continuous Delivery: Entrega Contínua;
  • Continuous Deployment: Implantação Contínua.

Segurança

A segurança deve ser considerada desde o início do desenvolvimento, e não somente depois que o sistema está pronto.

Autenticação

Responde:
"Quem é você?"

Pode utilizar:

  • Usuário e senha;
  • Tokens;
  • OAuth;
  • OpenID Connect;
  • Certificados;
  • Biometria.

Autorização

Responde:
"O que você pode fazer?"

Exemplo: um administrador pode possuir mais permissões que um usuário comum.

Menor privilégio

Cada usuário ou componente deve possuir somente as permissões necessárias.

Defense in Depth

Utiliza várias camadas de proteção.

Zero Trust

Nenhuma entidade deve ser considerada automaticamente confiável. O acesso deve ser continuamente validado.

Criptografia

Protege dados:

  • Em trânsito: durante a transmissão;
  • Em repouso: quando armazenados.

Segredos

Senhas, tokens e chaves privadas não devem ficar diretamente no código.

Observabilidade

É a capacidade de compreender o estado interno de um sistema através dos dados que ele produz.

Os três principais sinais são:

Logs

Registram acontecimentos.

Exemplo:
"Usuário autenticado com sucesso."

Métricas

Valores mensuráveis.

Exemplos:

  • CPU = 72%;
  • Memória = 68%;
  • Latência = 120 ms;
  • 10.000 requisições/minuto.

Traces

Acompanham uma requisição através de diferentes componentes.

Exemplo:
Frontend → API → Autenticação → Pedidos → Pagamento → Banco

Isso é especialmente importante em sistemas distribuídos.

OpenTelemetry

Projeto utilizado para instrumentar aplicações e coletar:

  • Traces;
  • Métricas;
  • Logs.

Inteligência Artificial e Arquitetura

A IA está influenciando tanto o desenvolvimento de software quanto os próprios sistemas que precisam ser arquitetados.

A IA generativa pode auxiliar em:

  • Geração de código;
  • Análise de código;
  • Documentação;
  • Diagramas;
  • Sugestões arquiteturais;
  • Identificação de problemas;
  • Refatoração;
  • Análise de alternativas.

Fluxo:
Requisitos → IA → Alternativas → Avaliação humana → Decisão → Implementação

A IA pode apresentar:

  • Informações incorretas;
  • Alucinações;
  • Recomendações inadequadas;
  • Problemas de segurança;
  • Problemas de privacidade;
  • Dificuldade de compreender contextos específicos.

Por isso, decisões arquiteturais críticas devem ser avaliadas por profissionais.

RAG

Retrieval-Augmented Generation
Permite buscar informações externas antes de gerar uma resposta.

Fluxo:
Pergunta → Busca de documentos → Contexto → LLM → Resposta

Pode consultar:

  • Documentos;
  • Bases internas;
  • Manuais;
  • Artigos;
  • Bases de conhecimento.

Agentes de IA

Agentes podem:

  • Interpretar objetivos;
  • Planejar;
  • Utilizar ferramentas;
  • Consultar APIs;
  • Executar ações;
  • Avaliar resultados.

Uma arquitetura pode ser:
Usuário → Agente → Ferramentas → APIs → Banco de Dados → LLM

Isso cria desafios relacionados a:

  • Segurança;
  • Controle de acesso;
  • Observabilidade;
  • Custos;
  • Confiabilidade;
  • Avaliação dos resultados.
