# 🎨 06 — Design Patterns

## O que são?

Design Patterns são soluções recorrentes para problemas de design de software.

Eles trabalham em um nível diferente dos padrões arquiteturais.

---

## Arquitetura

Trata da estrutura maior:

```text
Monólito
Microsserviços
Event-Driven
Hexagonal
```

## Design Patterns

Tratam de problemas específicos:

```text
Factory
Strategy
Observer
Adapter
Repository
Decorator
```

---

## SOLID

Princípios fundamentais de orientação a objetos:

### S — Single Responsibility Principle

Uma classe deve possuir uma responsabilidade principal.

### O — Open/Closed Principle

Entidades devem estar abertas para extensão e fechadas para modificação.

### L — Liskov Substitution Principle

Subtipos devem poder substituir seus tipos base sem quebrar o sistema.

### I — Interface Segregation Principle

Interfaces específicas são preferíveis a interfaces excessivamente grandes.

### D — Dependency Inversion Principle

Módulos de alto nível não devem depender diretamente de detalhes.

---

## Relação com arquitetura

```text
SOLID
  ↓
Design
  ↓
Componentes
  ↓
Arquitetura
```

O conhecimento de Design Patterns e SOLID ajuda a construir componentes que se encaixam melhor em arquiteturas maiores.
